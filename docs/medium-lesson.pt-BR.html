Desenvolvendo meu primeiro aplicativo com Flutter

Notas de aula do prof. Kleber de Oliveira Andrade · edição revisada em 17/11/2026

Vamos construir e compreender uma calculadora de índice de massa corporal (IMC) enquanto estudamos formulários, validação, estado e testes no Flutter. Ao final, você poderá explicar o caminho entre o texto digitado e o resultado, corrigir entradas inválidas e reiniciar a interface com segurança. O objetivo é aprender programação: este exemplo não substitui avaliação de saúde.

Esta revisão preserva a aula de 2019 e sua autoria, mas substitui o caminho ativo por código com null safety, componentes atuais, domínio puro e testes. A fórmula e as categorias gerais adotadas não mudam por gênero. O antigo desafio que propunha essa alteração foi retirado por não corresponder à referência usada aqui.

1. Delimite o problema antes de desenhar a tela

Usaremos a referência geral do CDC para adultos de 20 anos ou mais, fora da gestação. O IMC relaciona peso e altura: peso em quilogramas dividido pela altura em metros ao quadrado. É uma medida de triagem; não é diagnóstico e não distingue músculo de gordura. Crianças, adolescentes e gestantes exigem critérios específicos, não implementados neste exemplo.

IMC = pesoEmKg / (alturaEmMetros * alturaEmMetros)
70.5 / (1.75 * 1.75) = 23.020408163265305

As faixas gerais são: abaixo de 18,5; de 18,5 a menos de 25; de 25 a menos de 30; de 30 a menos de 35; de 35 a menos de 40; e 40 ou mais. A classificação usa o valor completo. Arredondamos somente a apresentação para uma casa decimal: 24,99999 pode aparecer como 25,0 e ainda pertencer à faixa anterior. A tela explica essa diferença.

Para manter o exercício delimitado, aceitamos 20–500 kg e 100–250 cm, ou 1–2,5 m, incluindo os extremos. Esses são limites operacionais do software didático, não limites clínicos nem uma afirmação sobre toda a população adulta. Não fornecemos metas de peso ou aconselhamento personalizado.

A versão validada é Flutter 3.50.0, com Dart 3.14.0. Instale essa versão pelo guia oficial. Abra um terminal no VS Code ou em seu editor e obtenha o projeto completo. O comando de execução abaixo usa Chrome, plataforma realmente validada nesta revisão.

3. Entenda onde cada responsabilidade mora

lib/domain/bmi.dart concentra unidades, leitura dos números, fórmula e classificação; não importa Flutter. lib/main.dart contém o tema, o formulário e os cartões. test/ verifica as regras e a interação. web/ contém o host validado no navegador; android/ e ios/ são hosts nativos regenerados com o SDK atual.

pubspec.yaml declara dependências e requisitos; pubspec.lock registra as versões resolvidas. .dart_tool/package_config.json é gerado pelo gerenciador de pacotes: substitui o papel do antigo .packages, e não deve ser editado à mão. build/ contém saídas geradas. .metadata é mantido pelo Flutter. Evite copiar arquivos gerados de outra máquina.

Widgets são descrições imutáveis da interface. Um StatelessWidget compõe a tela a partir dos dados recebidos; um StatefulWidget tem um objeto State que conserva o estado entre reconstruções. Column e Row organizam filhos, Padding cria espaçamento e LayoutBuilder permite escolher a composição conforme o espaço disponível. O cálculo não precisa conhecer esses componentes.

4. Modele e teste os dados antes da interface

Antes de implementar o domínio, escrevemos testes para fórmula, equivalência entre cm e m, vírgula decimal, limites de entrada e transições exatas. A primeira execução falhou porque o domínio ainda não existia. Isso registra o início do ciclo de teste, implementação e nova verificação; uma falha de ambiente não conta como evidência de regra incorreta.

O arquivo abaixo é o conteúdo completo de lib/domain/bmi.dart, com linhas vazias suprimidas apenas para a formatação no Medium. HeightUnit torna a unidade explícita; BodyMeasurements só pode ser criado pela fábrica que valida os dados. As propriedades são finais. A expressão regular aceita números decimais simples, e a conversão troca vírgula por ponto uma única vez na fronteira de entrada. Depois dessa fronteira, a fórmula recebe valores válidos.

/// Metric height units accepted at the input boundary.
enum HeightUnit {
  centimeters('cm', 100, 100, 250),
  meters('m', 1, 1, 2.5);
  const HeightUnit(this.symbol, this.divisor, this.minimum, this.maximum);
  final String symbol;
  final double divisor;
  final double minimum;
  final double maximum;
}
/// General CDC categories for adults 20+, not a diagnosis.
enum BmiCategory {
  underweight('Abaixo do peso', 'Menor que 18,5'),
  healthyWeight('Peso saudável', '18,5 a menos de 25'),
  overweight('Sobrepeso', '25 a menos de 30'),
  obesityOne('Obesidade · classe 1', '30 a menos de 35'),
  obesityTwo('Obesidade · classe 2', '35 a menos de 40'),
  obesityThree('Obesidade · classe 3', '40 ou mais');
  const BmiCategory(this.label, this.range);
  final String label;
  final String range;
  static BmiCategory fromBmi(double bmi) {
    if (!bmi.isFinite || bmi <= 0) {
      throw ArgumentError.value(bmi, 'bmi', 'Must be finite and positive');
    }
    const thresholds = [18.5, 25.0, 30.0, 35.0, 40.0];
    for (var i = 0; i < thresholds.length; i++) {
      if (bmi < thresholds[i]) return values[i];
    }
    return obesityThree;
  }
}
/// Validated, immutable values. UI input limits are operational, not medical.
final class BodyMeasurements {
  const BodyMeasurements._(this.weightKg, this.heightMeters);
  factory BodyMeasurements.parse(
    String weight,
    String height,
    HeightUnit unit,
  ) {
    return BodyMeasurements._(parseWeight(weight), parseHeight(height, unit));
  }
  final double weightKg;
  final double heightMeters;
  double get bmi => weightKg / (heightMeters * heightMeters);
  BmiCategory get category => BmiCategory.fromBmi(bmi);
  static double parseWeight(String text) => _parseNumber(text, 20, 500, 'kg');
  static double parseHeight(String text, HeightUnit unit) =>
      _parseNumber(text, unit.minimum, unit.maximum, unit.symbol) /
      unit.divisor;
  static double _parseNumber(String text, double min, double max, String unit) {
    final normalized = text.trim().replaceAll(',', '.');
    if (!RegExp(r'^\d+(?:\.\d+)?$').hasMatch(normalized)) {
      throw const FormatException(
        'Informe um número; use vírgula ou ponto decimal.',
      );
    }
    final value = double.tryParse(normalized);
    if (value == null || !value.isFinite || value < min || value > max) {
      final minimum = min
          .toStringAsFixed(min == min.roundToDouble() ? 0 : 1)
          .replaceAll('.', ',');
      final maximum = max
          .toStringAsFixed(max == max.roundToDouble() ? 0 : 1)
          .replaceAll('.', ',');
      throw FormatException('Use de $minimum a $maximum $unit.');
    }
    return value;
  }
}

Texto vazio, letras, zero, negativos, NaN, Infinity, números que transbordam, separadores misturados, notação científica e valores fora dos limites são rejeitados. Não removemos silenciosamente letras ou separadores: transformar uma entrada ambígua em outro número seria esconder o erro. Na unidade errada, 175 m e 1,75 cm também são recusados pelos limites.

A classificação percorre limiares ordenados. O uso de “menor que” faz 18,5 entrar na segunda categoria e 25 entrar na terceira, sem depender do texto arredondado. Para exercitar a API em um teste isolado, crie test/example_test.dart com este conteúdo completo, execute-o e remova-o depois se quiser evitar a duplicação dos testes já existentes:

import 'package:calculadora_imc/domain/bmi.dart';
import 'package:flutter_test/flutter_test.dart';
void main() {
  test('centimetres and metres agree', () {
    final cm = BodyMeasurements.parse('70,5', '175', HeightUnit.centimeters);
    final m = BodyMeasurements.parse('70.5', '1.75', HeightUnit.meters);
    expect(cm.bmi, closeTo(23.020408163265305, 0.000000001));
    expect(m.bmi, cm.bmi);
    expect(cm.category, BmiCategory.healthyWeight);
    expect(BmiCategory.fromBmi(24.99999), BmiCategory.healthyWeight);
    expect(BmiCategory.fromBmi(25), BmiCategory.overweight);
  });
}

5. Conecte o formulário ao domínio

Abra lib/main.dart no projeto clonado: ele contém a tela completa e executável. Os trechos seguintes são recortes explicativos desse arquivo; não substituem sozinhos o arquivo inteiro. O tema usa contraste, tipografia e espaçamento consistentes. Em telas largas o formulário e o resultado ficam lado a lado; em telas estreitas ou com texto muito ampliado, empilham-se em uma área rolável.

import 'package:material_ui/material_ui.dart';
import 'domain/bmi.dart';
void main() => runApp(const BmiApp());
class BmiApp extends StatelessWidget {
  const BmiApp({super.key});
  @override
  Widget build(BuildContext context) => MaterialApp(
    title: 'Calculadora de IMC',
    debugShowCheckedModeBanner: false,
    theme: ThemeData(
      colorScheme: ColorScheme.fromSeed(seedColor: const Color(0xFF006B64)),
      scaffoldBackgroundColor: const Color(0xFFF6F7F4),
      inputDecorationTheme: const InputDecorationTheme(
        border: OutlineInputBorder(),
        filled: true,
        fillColor: Colors.white,
        contentPadding: EdgeInsets.all(20),
      ),
    ),
    home: const BmiPage(),
  );
}

BmiPage é StatefulWidget porque guarda controladores de texto, focos, a unidade selecionada, o estado de validação e um resultado opcional. null significa que não há resultado válido. Os controladores e FocusNodes são criados uma vez no State e liberados em dispose; não devem ser recriados a cada build.

Form recebe uma GlobalKey<FormState>. Cada TextFormField chama a mesma regra do domínio dentro de seu validator. _validate captura FormatException e devolve uma mensagem de campo, em vez de deixar a aplicação encerrar. O teclado numérico é apenas uma ajuda de entrada: colagem e teclado físico ainda exigem validação real.

void _calculate() {
  setState(() => _submitted = true);
  if (!_form.currentState!.validate()) {
    setState(() => _result = null);
    if (_validate(() => BodyMeasurements.parseWeight(_weight.text)) != null) {
      _weightFocus.requestFocus();
    } else {
      _heightFocus.requestFocus();
    }
    return;
  }
  FocusScope.of(context).unfocus();
  setState(() {
    _result = BodyMeasurements.parse(_weight.text, _height.text, _unit);
  });
}
void _reset() {
  _form.currentState!.reset();
  _weight.clear();
  _height.clear();
  setState(() {
    _result = null;
    _unit = HeightUnit.centimeters;
    _submitted = false;
  });
  _weightFocus.requestFocus();
}

Ao calcular, validamos primeiro. Se houver erro, removemos o resultado e focamos o primeiro campo inválido. Se estiver tudo certo, criamos BodyMeasurements e reconstruímos a apresentação com setState. O botão Reiniciar limpa o Form, os dois controladores, resultado e erros, restaura centímetros e devolve o foco ao peso. Os testes também verificam esse comportamento após uma tentativa inválida.

Editar qualquer medida invalida o resultado anterior, evitando exibir um índice calculado com dados que já mudaram. Trocar centímetros por metros mantém o peso, limpa altura, resultado e erros, e pede nova altura; não reinterpretamos 175 como 175 metros. O teste dessa transição detectou e ajudou a corrigir um apagamento indevido do peso durante a implementação.

A ação Próximo do teclado move o foco do peso para a altura; Concluir na altura calcula. Os botões têm nomes visíveis e a região de resultado possui liveRegion para anunciar mudanças a tecnologias assistivas. A categoria é escrita por extenso, sem depender de cores. Medidas ficam somente na memória da sessão e não são enviadas pelo aplicativo.

6. Confira resultado, erro e recuperação

Execute o app e digite 70,5 no peso e 175 na altura em cm. Confira 23,0 e Peso saudável. Mude para metros: o peso permanece, a altura deve ficar vazia e o resultado anterior desaparece. Digite 1,75 e conclua pelo teclado; o resultado deve ser equivalente. Reinicie e tente calcular com campos vazios: devem aparecer mensagens nos campos, sem exceção e sem resultado antigo.

Também valide a leitura em uma janela estreita e com fonte ampliada. A captura a seguir usa uma viewport de navegador de 390×844; ela não representa um teste físico de telefone. A rolagem conserva acesso ao formulário, aos botões e ao resultado.

Cinco exercícios práticos

  1. Limiares sem arredondamento. Objetivo: estender os testes de classificação. Critério de conclusão: adicionar casos imediatamente abaixo, no valor exato e acima de 18,5, 25, 30, 35 e 40; todos devem passar e uma mudança de < para <= deve ser detectada.
  2. Validação compreensível. Objetivo: melhorar a experiência para uma entrada inválida sem mudar os limites. Critério de conclusão: escrever primeiro um teste para uma mensagem específica de campo vazio, implementar a mensagem e manter verdes os casos de letras, zero, negativos, não finitos e separadores misturados.
  3. Conversão explícita de unidade. Objetivo: oferecer conversão opcional da altura ao trocar cm/m. Critério de conclusão: escrever primeiro testes para 175 cm ↔ 1,75 m, entrada inválida e resultado antigo; implementar a conversão sem perder peso e atualizar a ajuda da interface.
  4. Acessibilidade do fluxo. Objetivo: verificar o caminho completo com teclado e leitor de tela. Critério de conclusão: registrar ordem de foco, anúncio de erro e de resultado, concluir um cálculo e reiniciar sem mouse; corrigir problemas e manter as diretrizes automatizadas aprovadas.
  5. Explicação verificável do cálculo. Objetivo: mostrar a substituição das medidas na fórmula após um resultado válido. Critério de conclusão: exibir 70,5 ÷ (1,75 × 1,75) no exemplo, testar a equivalência entre cm e m e garantir que a explicação desapareça ao editar, trocar unidade ou reiniciar.
